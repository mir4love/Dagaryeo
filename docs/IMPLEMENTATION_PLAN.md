# 다가려 구현 계획

## 목표와 완료 기준

첫 출시 순서는 이미지 모바일, PDF 모바일, 데스크톱 이미지와 PDF다. 첫 구현 결과의 완료 기준은 실제 기기에서 사진 선택 또는 촬영부터 로컬 OCR, 후보 검토와 수동 영역 지정, 새 이미지 재인코딩, 재열기 검증, 운영체제 공유까지 한 번에 수행되는 것이다.

## 플랫폼 책임

공통 TypeScript는 후보 규칙, 좌표 변환, 작업 상태, 정책과 디자인 토큰을 담당한다. iOS와 Android 어댑터는 사진 접근, ML Kit OCR, Skia 재인코딩, 파일 저장과 공유를 담당한다. macOS와 Windows는 독립 React Native 셸을 유지하며 각 플랫폼 OCR, 파일 대화상자와 PDF 엔진을 붙인다.

## 단계 A

1. PII 규칙과 좌표 변환을 단위 테스트로 구현한다.
2. M01부터 M05까지 실제 이미지 흐름을 구현한다.
3. 불투명 픽셀 마스크를 새 PNG로 재인코딩하고 메타데이터가 복사되지 않게 한다.
4. 출력 파일을 다시 열어 형식, 크기, 선택 영역을 검증한 뒤 공유를 허용한다.
5. D01부터 D04까지 상태가 연결된 데스크톱 셸을 만든다.
6. iOS와 Android 실제 기기에서 OCR을 포함한 전체 흐름을 검증한다. iOS ML Kit 배포 바이너리는 Apple Silicon 시뮬레이터 아키텍처를 제외하므로 시뮬레이터는 컴파일 검증까지만 수행한다.

## 단계 B 선행 조건

PDF 엔진 두 개 이상의 POC에서 텍스트 객체 제거, 주석·폼·첨부·메타데이터 정리, 저장 후 재추출 검사가 확인되어야 한다. 상업 배포 라이선스와 iOS, Android, macOS, Windows 지원 범위를 확정하기 전에는 PDF 저장을 활성화하지 않는다.

## 단계 C 선행 조건

다중 파일 큐와 파일별 검토 상태가 먼저 안정화되어야 한다. StoreKit, Play Billing, PC 서명 토큰은 서로 다른 권한 어댑터로 구현하고 실제 상품 ID와 서명 키가 없는 개발 환경에서는 테스트 권한만 제공한다.

## 현재 미검증 항목

- Windows 네이티브 빌드는 Windows 11과 Visual Studio 환경에서 확인해야 한다.
- iOS와 Android의 촬영·OCR·마스킹·공유 전체 흐름은 실제 기기에서 확인해야 한다.
- HEIC 입력 방향과 대형 이미지 메모리는 대표 실제 기기에서 측정해야 한다.
- PDF 안전 내보내기는 미구현이며 사용자 UI에서 비활성이다.

## 완료된 빌드 검증

- Android 디버그 APK: Gradle `assembleDebug` 성공
- iOS: CocoaPods 설치 및 시뮬레이터 대상 네이티브 컴파일 성공
- macOS: CocoaPods 설치 및 Apple Silicon Debug 빌드 성공
